## 발견 경위

이번 주 계획(#32) 기능 점검의 "빨간 글" 단계에서 DB에 규칙 밖 마감일을 직접 넣어 보다가 발견했다.
API는 마감일을 YYYY-MM-DD로만 받지만 DB의 마감일 칸에는 검사 규칙이 없어서 DB를 직접 고치면 규칙 밖 값이 들어간다.

## 함께 확인한 것 (임시 DB, 실제 DB는 쓰지 않음)

마감일을 아래 값으로 바꿨을 때 보드(`GET /tasks`), 이번 주 계획(`POST /tasks/weekplan`), 오늘 브리핑(`POST /tasks/briefing`)은
모두 200이었고 서버 오류(500)는 없었다.

- `NEXTWEEK`, `2026-13-45`, `20261030`: 기한 초과가 아님
- `""`(빈 문자열): 기한 초과 true → 이 문서의 F-002
- `2025`: 기한 초과 true

우선순위(priority)는 DB에 검사 규칙(CHECK)이 있어 규칙 밖 값을 넣을 수 없었다.

## 해결

기한 초과 계산에서 빈 문자열 마감일을 "마감일 없음"으로 본다.

- `backend/app/routes/tasks.py`: `_to_task`의 기한 초과 계산, 목록 정렬 SQL의 기한 초과 조건
- `backend/app/briefing.py`: 오늘 브리핑과 이번 주 계획이 함께 쓰는 SQL의 `overdue` 계산

## 남은 것 (이번에 고치지 않음)

- 빈 문자열 마감일 카드가 정렬에서 마감일이 있는 카드 중 가장 앞에 올 수 있다. 이번 테스트가 다루는 문제가 아니라 범위에서 뺐다.
